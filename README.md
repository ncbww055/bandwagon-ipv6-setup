## 搬瓦工 IPv6 怎么开启

开启流程就三步，全程不用敲命令：

1. 登录 KiwiVM 控制面板，找到 IPv6 Management 页面。默认状态下会显示 "Currently, no IPv6 subnet is assigned"，即尚未分配子网。
2. 点击激活按钮，系统会分给你一个 /64 的 IPv6 子网。
3. **重启 VPS**。这一步不能省，激活之后不重启是不生效的，很多人卡在这一步以为功能是坏的。

重启后验证也简单。SSH 登录机器，运行 `ifconfig`，能看到一个名为 `ipv6net` 的网络接口，`inet6` 后面就是分到的地址，形如 `2607:8700:5500:abcd::2/64`。用 `ping6 google.com` 测一下连通性，能通就说明一切正常。

> 默认只配置了子网里的 `::2` 这一个地址，整段 /64 都归你。想加更多地址，执行 `ip -6 addr add 你想要的地址/64 dev ipv6net` 即可。

如果 ping 不通或者看不到地址，先重启一次，大部分问题到这一步就解决了。还不行的话，可以检查 `/etc/network/interfaces` 配置文件，或者用 KiwiVM 面板里的智能助理 Assistant Amy 排查。前面速览里提到的 20G KVM 年付只要 $49.99，下单后按这三步走，十分钟内就能拿到 IPv6 地址：👉 [开通 20G KVM 并在面板激活 IPv6](https://bandwagonhost.com/cart.php?a=add&pid=44&aff=74518)

## 它的 IPv6 是原生还是隧道

这是前排教程普遍没讲透、但实际使用中影响最大的一个问题：搬瓦工面板里一键开启的 IPv6，底层是通过隧道实现的。有用户在 DC1 机房的限量版套餐上实测发现，机器内的 `ipv6net` 接口是一个 sit 隧道（MTU 1480，POINTOPOINT 模式），隧道对端的服务器甚至是 Vultr 的机器。也有第三方教程指出搬瓦工美西机房的 IPv6 同样是隧道方案、未对线路做优化。各机房实现细节可能不完全一样，但至少可以确定它走的不是纯原生路径。

这带来几个实际影响：

- 隧道方案意味着 IPv6 流量要绕经隧道服务器转发，速度和延迟不要按原生 IPv6 的预期来。社区里对它的评价大致是“略胜于无”。
- MTU 被固定在 1480（以太网标准是 1500），个别对 MTU 敏感的应用可能需要手动调整。
- 稳定性上它依赖隧道对端的可用性，用来跑对 IPv6 可用性要求很高的生产服务前，建议先测一段时间。

反过来说，如果你的需求是开发测试、让服务能被 IPv6 网络访问到、或者接入一些只走 v6 的节点，隧道方案完全够用，而且省去了自己找隧道服务商、配置 Tunnelbroker 的整套流程。在面板里点两下就能得到一整段 /64，这个便利是实打实的。
